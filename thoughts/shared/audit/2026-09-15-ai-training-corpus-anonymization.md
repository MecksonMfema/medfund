# AI Training Corpus — Anonymization Audit

## Purpose

Per grilling decision **G4**, Tranche 1 trains fraud models **across tenants** from the labeled corpus that accumulates in `ai_predictions_store`. Cross-tenant is the default; a formal anonymization audit gates any Phase 2 artifact from serving production traffic.

This document is that gate. When the auditor signs off (below), the release PR flips `MEDFUND_TRAINING_AUDIT_SIGNED_OFF=true`; `scripts/train_fraud.py` refuses to write an artifact when the flag is unset.

## What the auditor reviews

1. This document, column-by-column against every field emitted by the Phase-1 corpus reader.
2. A 100-row preview generated by:
   ```bash
   cd services/python/ai-service
   uv run python scripts/dump_corpus_sample.py --output /tmp/corpus-sample.jsonl
   # (add --line HEALTH to scope to a single line)
   ```
   The script reads `ai_predictions_store` directly and writes one row per line to a JSONL file. Deterministic seed (`--seed 42` by default).
3. Any downstream redaction rules — Phase 2's trainer only consumes the columns listed as "USED IN TRAINING" below; everything else is skipped by the trainer and never re-anonymized.

## Redaction rules to add before sign-off

1. **`created_at` truncation** — the sample-dump script truncates to month (`2026-09-01T00:00:00Z`) so a specific tenant × specific-day claim can't be re-identified through the corpus.
2. **`_review_feedback` free-text** — either drop entirely from the training-facing view, or run through a regex-based PII scrubber (email/phone/name patterns) before display. Recommendation: drop for Tranche 1 since it isn't used in training.
3. **Column allowlist** — the sample-dump script emits only the columns listed above. Any new column added to `ai_predictions_store` in future work triggers a re-review; the emit list is code-enforced.

## What flipping the env var does

When `MEDFUND_TRAINING_AUDIT_SIGNED_OFF=true`:

- `scripts/train_fraud.py` (Phase 2, not yet shipped) proceeds with artifact writes.
- `scripts/dump_corpus_sample.py` is always runnable — it is the review artifact, not a training artifact.
- `resolve_fraud_model()` (Phase 3) is unaffected — it loads whatever exists in MinIO. The gate is on **producing** artifacts, not on serving them.

When it is absent or `false`:

- `scripts/train_fraud.py` exits with code 3 and prints a pointer to this doc.
